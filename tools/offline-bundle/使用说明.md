# Jev 托管 AI · 本地 Laya 离线整合包

这个目录是一个**自包含、可离线运行**的整套环境：扩展 + 本地 Laya 决策模型 + Python 运行时 + 控制脚本。
装好之后，托管决策**全程不联网**，不需要 Jev 密钥，不产生任何 API 费用。

---

## 1. 这个包里有什么

```
jev-helper-offline/
├── 启动.cmd              ← 双击这个
├── 使用说明.md            ← 本文件
├── extension/            ← 扩展本体，在 chrome://extensions 里加载这个文件夹
├── model/
│   └── laya-multilingual/  ← 模型权重（647 MB），多语言检查点
├── venv/                 ← Python 运行时（PyTorch + CUDA + laya，约 4.8 GB）
└── tools/                ← 服务启动与自检脚本
```

整个目录约 5.4 GB，其中 PyTorch 的 CUDA 运行库占了大头。
用 CPU 版重建（`build-offline-bundle.ps1 -Device cpu`）能降到约 1.5 GB。

| 组成 | 说明 |
|---|---|
| `extension/` | 构建好的 Chrome/Edge MV3 扩展，构建指纹见 `match.meta.build` |
| `model/laya-multilingual/` | `convaiinnovations/laya-multilingual`，多语言检查点 |
| `venv/` | Python 3.13 虚拟环境，已装好 `laya[serve]` 与 CUDA 版 PyTorch |
| `tools/` | `laya-ctl.*`（启停/状态/日志）、`laya-serve-local.py`（服务本体）、`laya-check.py`（协议自检） |

## 2. 运行要求

- Windows 10 / 11
- NVIDIA 显卡（本次为 RTX 3060 12GB）。**需要** NVIDIA 驱动，版本 525 以上
- 约 6 GB 磁盘空间
- 浏览器：Chrome 或 Edge

> **为什么不是仓库里那个 `npm run laya`？**
> 那个走 `laya_mlx`，是 MLX 移植版，**只能跑在 Apple 芯片 Mac 上**，
> 仓库文档里也写明 Windows / Intel Mac / Linux 无法运行。
> 这个整合包用的是 PyPI 上的 `laya`（纯 PyTorch，CPU/CUDA/全平台）自带的
> `laya-serve`，对外协议与 Jev 完全一致，扩展不需要任何改动。

## 3. 上手（三步）

### 第 1 步：启动服务

双击 **`启动.cmd`**。

它会启动服务、等待就绪，然后**自动发一次真实决策请求做协议自检**。
看到这一段就是成功了：

```
  ============================================================
   已就绪
  ============================================================
```

自检通过说明：模型加载正常、中文候选能被正确理解、返回的选择项确实在你给出的候选里。
扩展会拒绝不遵守协议的回答，所以这一步不过就不能用。

服务默认只监听 `127.0.0.1:8742`，**不需要令牌**。

### 第 2 步：加载扩展

1. 浏览器打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 右上角开启 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本目录下的 **`extension`** 文件夹

### 第 3 步：配置扩展

打开游戏页面 → 点扩展图标 → **设置**：

| 设置项 | 填什么 |
| --- | --- |
| 模型来源 | **本地 Laya** |
| 本地服务地址 | `http://127.0.0.1:8742/v1`（默认值，不用改） |
| 本地访问令牌 | **留空** |
| 本地模型名称 | `laya` |

1. 点 **保存设置**。浏览器会问是否允许访问该地址，点 **允许**。
2. 点 **测试模型连接**。按钮变绿并显示模型名 `laya-multilingual` 就成功了。
3. 进对局，点 **开启托管**。

## 4. 命令

| 命令 | 作用 |
| --- | --- |
| `启动.cmd` | 启动并自检（双击默认） |
| `启动.cmd status` | 现在跑着什么、模型载入没有、权重齐不齐 |
| `启动.cmd stop` | 停止服务 |
| `启动.cmd restart` | 重启 |
| `启动.cmd test` | 只做协议自检，不重启服务 |
| `启动.cmd logs` | 看服务日志末尾 40 行 |

日志在 `tools/../.laya-server.out.log` 和 `.laya-server.err.log`。

## 5. 离线说明

**装完之后，以下操作全程不联网：**

- 启动服务、加载模型、推理决策
- 扩展的全部功能

服务启动时会强制 `HF_HUB_OFFLINE=1` 和 `TRANSFORMERS_OFFLINE=1`，
并且检查点是从**本地目录**加载的，不会去碰 huggingface.co。
如果真有代码试图访问网络，会直接报错而不是静默挂起。

**只有安装这一步需要联网**（已经做完了）：下载 PyTorch 和模型权重。

## 6. 注意事项

### 这个目录要放在固定位置

`venv/` 里记录了 Python 解释器的**绝对路径**。把整个目录拷到别处后，
`venv\Scripts\python.exe` 会失效。此时二选一：

- 放回原路径；或
- 在新位置重新建环境（见第 7 节），模型和脚本可以直接复用

模型（`model/`）和脚本（`tools/`）本身是可移动的，只有 `venv/` 不是。

### CUDA 不可用时会退回 CPU

如果没装 NVIDIA 驱动或驱动太旧，服务会退回 CPU 推理。
**能跑，但慢很多**（单次决策从毫秒级变成秒级），多组决策时托管会明显滞后。
用 `启动.cmd status` 可以看到当前用的是哪个设备。

### 这个模型的定位

Laya 的上下文只有约 1024 token，而一局的战况通常更长，服务会把短字段排前面、
从末尾截断。所以**本地模型的决策质量明显弱于 Jev 云端**，实测在生产类决策上偏保守
（爱选「等待」）。属实验用途，不保证胜率。

另外本地模型只能做**选择题**（`choices` 模式），不支持「指挥官」模式
——那是给 OpenAI 兼容的大模型用的，本地小模型读不动战况简报。

## 7. 重建 Python 环境

只在需要换机器、换路径时用。日常使用不需要。

```powershell
cd <本目录>
python -m venv venv
.\venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu124
.\venv\Scripts\python.exe -m pip install "laya[serve]"
.\venv\Scripts\python.exe tools\laya-model-fetch.py --dir model\laya-multilingual
```

最后一行会从 ModelScope 拉约 647 MB 的权重。
如果这台机器连不上 ModelScope，也可以手工下载
[convaiinnovations/laya-multilingual](https://www.modelscope.cn/models/convaiinnovations/laya-multilingual)
的以下文件，放进 `model\laya-multilingual/`：

```
configuration.json
rl_agent_config.json
model.safetensors
encoder/config.json
tokenizer/tokenizer.json
tokenizer/tokenizer_config.json
```

## 8. 排查

| 现象 | 原因与处理 |
| --- | --- |
| 启动报找不到 Python 环境 | 整合包不完整，或被移动过（见 6.1），需要重建环境 |
| 启动报 `checkpoint incomplete` | `model/laya-multilingual/` 缺文件，重跑第 7 节最后一行 |
| 自检超时 | 第一次推理要加载模型，CUDA 上通常几秒内；超时先看 `启动.cmd logs` |
| 自检报答案不在候选里 | 模型或权重装错了，`启动.cmd status` 会显示实际载入的模型名 |
| 扩展保存时提示须使用 HTTPS | 地址不是本机或私有网段。本机就用 `127.0.0.1:8742` |
| 扩展提示访问权限被撤销 | 重点「保存设置」并允许访问该地址 |
| 端口 8742 被占用 | `启动.cmd start -Port 8743`，同时把扩展里的地址也改成 8743 |
| 界面上模型很「怂」，一直等待 | 见 6.3，这是本地小模型的已知局限，不是装错了 |

## 9. 局域网共享

让同一局域网的其它电脑（可以没有 Python）用上这个模型：

```
tools\laya-ctl.cmd start -Lan -Python <本目录>\venv\Scripts\python.exe -Model <本目录>\model\laya-multilingual
```

会打印局域网地址和令牌。对方在扩展里填那个地址和令牌、授权即可。

注意：服务端同一时间只跑一个推理，多台电脑同时托管会排队，响应变慢。
Windows 首次监听所有网卡时会弹防火墙提示，需要允许。

## 10. 这个包是怎么来的

由仓库里的 `tools/build-offline-bundle.ps1` 组装，需要时可重新生成：

```powershell
.\tools\build-offline-bundle.ps1 -Destination D:\jev-offline
```

它会构建扩展、建好带 CUDA 的 Python 环境、从 ModelScope 拉权重、再把启动器和本文拷进来。
生成过程需要联网约 3.1 GB；**生成出来的包本身运行时不联网**。

更完整的原理说明在 jev-helper 仓库的 `docs/local-laya.md`。
